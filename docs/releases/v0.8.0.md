# Orchestrator chart v0.8.0

This chart coordinates the generic plugin foundation (`v1alpha`) with ordinary
Deployment admission and the deployment queue. `appVersion` identifies the
Control Plane version, not a shared version for all components.

## What changes

- Adds the Plugin Manager routes and IAM platform-principal routes, workload
  identity exchange configuration, plugin entitlement trust, and the native
  plugin gateway profile. These profiles remain disabled by default. This chart
  contains no commercial plugin package or harness; Progressive Rollouts remains
  a separate private delivery (G2).
- Adds ordinary Deployment admission profiles. The Control Plane uses one
  IAM static-token platform-principal identity for every organization; the Data
  Plane calls the HTTPS Core Gateway with that identity. Both profiles are
  disabled by default.
- Routes plugin discovery/invocation, plugin management, deployment outcome
  acknowledgement, operation inventory, and the per-Environment deployment
  queue to their owning services.
- The coordinated Data Plane 4.0.0 changes the raw deployment API default to
  `queue`; this is a breaking API default change. Organization-token requests
  still return `environment_busy` rather than entering the queue.
- Keeps the NATS bootstrap Job under Helm ownership instead of expiring it by
  TTL, so Helm waits and recovery do not lose a managed release resource.
- IAM uses `Recreate` during upgrades. Expect a brief authentication
  interruption while the replacement starts.

The plugin contract is `v1alpha`. Its documented boundary permits an installed
plugin to reach every organization where it is enabled; organizations share
that plugin's database. This is not a tenant-isolation guarantee. Plugin
workloads use the separate `native-plugin-runtime` chart, version `0.1.0`, and
require Kubernetes 1.30 or newer. Core-only installations do not acquire that
runtime requirement.

## Candidate component set

The selected target versions are CP 3.1.0, DP 4.0.0, IAM 2.5.0, Runner 3.1.0,
Console 1.4.0, CLI 2.1.0, and provider 2.1.0. The chart's image references have
not yet been updated to the qualified public digests for this set. This source
snapshot is not an installable or publishable release until those pins and the
compatible set are verified.

## Upgrade and recovery

The baseline is chart 0.7.0. Back up databases, encryption keys, Helm values,
and Terraform/OpenTofu state; drain Deployments before switching writers.
Migrations are additive, and Down migrations are not an application recovery
procedure. After writes under the new schema, do not roll back to a 0.7.0
revision: its IAM, Control Plane, and Data Plane do not provide a compatible
writer for the new schema. Recovery must retain the additive schema and use a
reviewed, schema-compatible 0.8.0 application revision or forward repair. That
recovery path remains to be qualified against the final public image digests.

Plugin identity setup follows installation: create the workload binding and
admission checker as platform principals with the Plugin Manager client. The
Control Plane verifies the binding and principal type; the checker token is
configured through the existing `nativeExternalDeployment` Secret path.
