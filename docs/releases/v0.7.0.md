# Orchestrator chart v0.7.0

This chart coordinates the Module Version Management upgrade.
Its version is independent of the versions of its application components.

## What changes

- Route Module catalogue, version, history, Pin and related API requests through
  the stock installation.
- Use namespace-qualified Runner callback addresses so jobs in another namespace
  reach the intended installation.
- Preserve the normal server, gateway, IAM, database and Runner architecture.

## Required component set

The chart pins CP 3.0.0, DP 3.2.0, IAM 2.4.0,
Runner 3.1.0 and Console 1.3.0 to verified public image digests.
Publishing clients are CLI 2.0.0 and Terraform/OpenTofu provider 2.0.0.

`appVersion` identifies the Control Plane version, not a shared version for all
components. Keep the complete component set together when upgrading. The image
tags include immutable digests; changing only the tag text does not select a
different image.

## Upgrade and recovery

The supported baseline is stock chart 0.6.1. Back up platform databases, encryption
keys, Helm values and Terraform/OpenTofu state. Drain Deployments and prevent old
and new Module writers from running concurrently.

This is a breaking authoring upgrade even though the chart is pre-1.0. Migrate
clients from mutable definitions to complete version publication and explicit
promotion. Resource Types become immutable, output declarations are required
where constrained, and retained catalogue history survives teardown.

Historical identities and snapshots must remain usable. After new version or
Pin writes, recover with a compatible application revision or forward repair.
Do not run destructive Down migrations as an automatic Helm rollback procedure.

Use the published image digests when reproducing an installation or recovery.

## Qualification and known limits

The stable component set passed a local upgrade rehearsal from public chart 0.6.1.
The rehearsal preserved an existing Module's exact version identity and source,
then exercised publication, promotion, normal Runner deployments, an update and
historical rollback. Encrypted outputs were decrypted and checked by the caller.
The public CLI and registry-installed Terraform/OpenTofu provider also exercised
lifecycle operations, retained-history import, Pins and append-only notes.

A separate installation on empty application databases passed version
publication, promotion, real Runner execution and encrypted-output checks.
The public CLI and both registry-installed providers passed their lifecycle
checks against that fresh installation as well.

Recovery was tested by restoring a known-good **post-upgrade** Helm revision
after an invalid application configuration. Module history and managed definitions
remained intact. This does not establish that the old mutable-authoring binaries
can safely write to the upgraded database.

The CLI's optional update notification no longer recommends an older version.
