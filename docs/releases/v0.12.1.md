# Platform Orchestrator Helm chart 0.12.1

This patch pins Data Plane `4.4.1` by its qualified public image digest. Readiness
inspection now distinguishes a verified Environment without deployment history
from an actual identity change. Actual Core or recorded-history identity
mismatches still return a conflict. No deployment history or baseline is created.

The compatible set is Control Plane `4.1.0`, Data Plane `4.4.1`, IAM `2.8.1`,
Runner `3.3.0` and Console `1.7.0`. Use CLI `2.5.1`, released separately, for the
correct bearer-session expiry in the login success message. The provider remains
`2.4.0`.

The other image pins, chart configuration and database migrations are unchanged
from `0.12.0`. Follow its [upgrade and recovery requirements](v0.12.0.md), including
the IAM-first order when upgrading an earlier installation. Back up all
installation databases and key material, and verify restoration before upgrading.
An image or Helm revision rollback does not reverse schemas from earlier upgrades.

Runner `3.3.0` retains the explicitly accepted findings in its unchanged OpenTofu
executable. Its [version-scoped disposition](https://github.com/stellwerk-labs/platform-orchestrator-runner/blob/v3.3.0/docs/releases/vendor-residuals-v3.3.0.md)
records the affected binary, findings and qualification limits.
