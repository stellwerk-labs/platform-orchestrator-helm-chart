# Orchestrator chart v0.9.0

This chart adds the gateway routes needed for Environment-scoped Draft capture
and explicit Draft test deployments. Custom route overrides must include the
matching routes before enabling these workflows. The execution-catalogue
operation remains routed to the Control Plane, where the Data Plane principal
check is enforced.

Use this chart with the compatible Control Plane v3.2.0 and Data Plane v4.1.0,
their matching gateway configuration, and the qualified IAM, Runner, and Console
set. Existing published HTTP operations remain available. Unsupported servers
must reject new Draft test routes; clients and the gateway must not substitute
an ordinary Default deployment.

## Upgrade and recovery

Control Plane and Data Plane Deployments now default to `Recreate`. During an
upgrade Kubernetes stops the old revision before starting the new one. Expect a
brief API and worker interruption. Keep this strategy for schema-changing
upgrades; explicit `RollingUpdate` overrides are unsafe for that path. Upgrade
Data Plane first, verify it with the existing Control Plane, then upgrade Control
Plane. Do not run old and new writers of the same service together.

Control Plane migrations 49 through 51 retain interface versions, Draft
revisions, and test snapshots. Data Plane migrations 36 and 37 retain exact
interface selections and executable Draft provenance. Older Control Plane or
Data Plane binaries refuse the new schemas. Do not roll back to old application
images or use destructive Down migrations after these schemas are written. Keep
the compatible schema and use schema-compatible images or a forward fix. Back up
databases, encryption material, Helm values, and Terraform/OpenTofu state before
upgrading.
