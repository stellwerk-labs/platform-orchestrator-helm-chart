# Orchestrator chart v0.8.0-rc.1

This candidate coordinates the generic plugin foundation (`v1alpha`), ordinary
Deployment admission and the deployment queue. `appVersion` remains `3.1.0`,
the Control Plane semantic version, not a common version for all components.
This prerelease is intended for coordinated testing, not production use.

## What changes

- Adds Plugin Manager and IAM platform-principal routes, workload identity
  exchange, plugin entitlement trust and the native plugin gateway profile.
  Plugin features remain disabled by default. No commercial plugin package or
  test harness is included.
- Adds ordinary Deployment admission profiles, disabled by default. The Control
  Plane uses one IAM static-token platform-principal identity across organizations;
  the Data Plane calls the HTTPS Core Gateway with that identity.
- Routes plugin discovery/invocation, management, outcome acknowledgement,
  operation inventory and the per-Environment queue to their owning services.
- Data Plane 4.0.0 changes the raw deployment API default to `queue`, a breaking
  default change. Organization-token requests still return `environment_busy`.
- Keeps the NATS bootstrap Job under Helm ownership rather than expiring it by
  TTL, so Helm waits and recovery retain their managed resource.
- IAM uses `Recreate` during upgrades, causing a brief authentication interruption.

Plugin workloads use the separate `native-plugin-runtime` chart and require
Kubernetes 1.30 or newer; Core-only installations do not acquire that runtime
requirement. The ordinary runtime `v0.1.0-rc.1` has passed public-consumer
qualification but remains separate, not a Core chart dependency or bootstrap alias.
The contract is `v1alpha`; first-party plugins share their own database across
enabled organizations, while Core enforces organization-scoped effects.

Before adopting this candidate, require the complete chart CI contracts and the
exact public-artifact set rehearsal: fresh install, upgrade from chart 0.7.0,
legacy-data preservation, new writes, restarts and compatible recovery on amd64
and arm64. Previous private/source-built evidence does not qualify this set.

## Upgrade and recovery

Back up databases, encryption keys, Helm values and Terraform/OpenTofu state;
drain Deployments before switching writers. Migrations are additive. Down
migrations are not application recovery. After new-schema writes, do not roll
back to a 0.7.0 revision: its IAM, CP and DP are not compatible writers for the
new schema. Retain the additive schema and use a reviewed, schema-compatible
0.8.0 application revision or forward repair. Verify this recovery path against
the final public image set before upgrading.

After installation, create workload bindings and the admission checker as
platform principals through the Plugin Manager client. The Control Plane
verifies the binding and principal type; configure the checker token through
the existing `nativeExternalDeployment` Secret path.
