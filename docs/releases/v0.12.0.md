# Platform Orchestrator Helm chart 0.12.0

## Coordinated components

The chart pins the public images for Control Plane `4.1.0`, Data Plane `4.4.0`,
IAM `2.8.1`, Runner `3.3.0` and Console `1.7.0` by digest. Use CLI `2.5.0`,
released separately. The Terraform/OpenTofu provider remains `2.4.0`.

Runner `3.3.0` retains the explicitly accepted security findings in its unchanged
OpenTofu executable. See its
[version-scoped disposition](https://github.com/stellwerk-labs/platform-orchestrator-runner/blob/v3.3.0/docs/releases/vendor-residuals-v3.3.0.md)
for the affected binary, findings and qualification limits.

## Database transport security

Control Plane, Data Plane and IAM expose `DATABASE_SSLMODE`, defaulting to
`disable` for compatibility. `require` encrypts without plaintext fallback;
`verify-full` also verifies the certificate and hostname using the configured
CA. Apply the existing Secret-file configuration profiles and restart each
service after changing startup settings. The chart does not issue or rotate
database certificates. See [Database TLS](../database-tls.md).

## Optional Infracost estimates

The gateway routes `/platform-settings/cost-estimation` to the Data Plane.
Matching Console Administration lets installation administrators enable optional
estimates and save, replace or clear their own Infracost API key. Estimates
default disabled; the chart does not provide a customer key or store one in
Helm values. The Data Plane wraps the credential with Vault Transit; ordinary
settings reads expose presence rather than the secret.

The compatible Runner includes the estimation tool. Unavailable credentials
skip estimates without blocking deployment. Each dispatch, including retries,
uses the current credential. Job and ECS task-definition administrators, remote
JetStream readers and diode frame readers remain inside the existing execution
credential trust boundary. Rotation affects future dispatches and does not
revoke a key already copied into queued work. Observation estimates appear in
runtime logs; private plan output remains excluded.

## Managed logs and browser routes

Matching Console and CLI request server-managed log capture by default; raw API
callers opt in with `managed_logs: true`. The Data Plane creates a fresh age key
for each deployment and stores only its Vault Transit-wrapped private identity.
Plaintext retrieval requires an explicit `deployment_logs_read` grant at the
organization, project or environment scope covering that deployment. Viewer,
Deployer and ordinary metadata-read grants alone no longer authorize decrypted
log contents.
Organization Admins retain access through `manage_all`; custom roles and service
users need explicit grants. Ciphertext retrieval retains its existing permission.

The Console Logs tab uses authenticated managed decryption and sends no
`DecryptKey` header. The gateway CORS allowlist includes `DecryptKey` for legacy
caller-owned browser clients. Custom `global.gatewayApi.backend.cors.allowHeaders`
lists must include it if needed. It is not forwarded to external authentication
or exposed in responses. CORS does not grant log permission or change key custody.
Historical caller-owned logs still require their original private key.

## Upgrade and recovery

1. Back up the installation databases, Vault Transit key material and retained
   key versions; verify independent restoration before upgrading.
2. Upgrade IAM `2.8.1` first so the permission catalog contains
   `deployment_logs_read`, then Control Plane `4.1.0` and Data Plane `4.4.0`.
   Replace every backend writer before enabling the new access path.
3. Use the matching Runner and clients, grant dedicated log access where needed,
   and verify managed capture and authorized plaintext retrieval in isolation.
4. Enable estimates only when desired and supply the customer's Infracost key
   through Administration, then verify an isolated execution.

Data Plane migration `43` retains managed log identities. Keep its rows and the
historical Vault Transit key versions throughout backup retention. Its Down
migration drops those identities and loses automatic log access unless restored.
Keep the new schema when disabling the feature; do not roll old images over new
schemas. A downgrade requires the coordinated database and secret restoration
procedure, not only a Helm rollback. Existing caller-owned keys are not recovered
by managed storage. Commercial plugins, licences and private instance credentials
remain separate from this public chart.
