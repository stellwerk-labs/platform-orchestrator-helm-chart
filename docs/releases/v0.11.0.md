# Platform Orchestrator Helm chart 0.11.0

## Compatible versions

| Component | Version |
| --- | --- |
| Control Plane | `4.0.0` |
| Data Plane | `4.3.0` |
| IAM | `2.7.0` |
| Console | `1.6.0` |
| Runner (unchanged) | `3.2.0` |
| CLI | `2.4.0` |
| Terraform/OpenTofu provider | `2.4.0` |
| Generic plugin runtime and chart | `0.1.3` |

The chart pins its server images by digest. CLI, provider and plugin runtime
versions are separate releases. Commercial plugins also need matching releases
that implement maintenance coordination; this chart does not install them.

## Installation administration

The chart routes browser session status and genuine activity to IAM, session
policy to IAM, deployment maintenance policy to the Data Plane, and combined
maintenance readiness to the Control Plane. The matching Console provides
Administration tabs for Plugins and Configuration. Installation operator grants
control access to these settings.

Browser inactivity defaults to 15 minutes (`iam.config.BROWSER_SESSION_IDLE_TIMEOUT`)
and CLI user-token lifetime to 2 hours (`iam.config.CLI_SESSION_TOKEN_TTL`).
These chart values initialize stored policy; changing ordinary environment values
does not silently replace an existing policy. Operators can change it through
Administration or the installation API, and changes apply to existing sessions.
`SESSION_POLICY_RESET_TO_DEFAULTS` is an explicit recovery switch. Return it to
`"false"` after recovery. Service and Runner tokens keep their existing policies.

Maintenance stops new deployments and managed observations while admitted work
drains. Use the combined readiness status, including plugin and unresolved-work
counts, before starting maintenance work. An unknown status is not readiness.
The corresponding plugin versions must implement this coordination contract.

## Provider retirement and upgrade order

Control Plane 4.0.0 accepts Provider retirement with HTTP 202 rather than deleting
immediately with HTTP 204. Matching clients track the retained row until cleanup
is confirmed. A retirement request does not destroy workloads. Remove retained
resources through the normal lifecycle before the orchestrator can delete their
Provider configuration.

1. Back up the installation databases and verify independent restoration.
2. Upgrade every Control Plane and Data Plane writer with
   `control-plane.config.PROVIDER_RETIREMENT_ENABLED: "false"`.
3. Confirm all running image digests, no predecessor writers, and complete
   Provider-usage protocol coverage. Missing state is unresolved, never empty.
4. Upgrade the Console, CLI and Terraform/OpenTofu provider to matching clients.
5. Set `PROVIDER_RETIREMENT_ENABLED: "true"` explicitly and test an isolated
   Provider before requesting retirement of customer Providers.

Retirement is disabled by default. Requests return HTTP 503
`provider_retirement_not_enabled` until activated. Once accepted, only cleanup
removals remain permitted for that Provider; new provisioning is refused.

## Recovery

Database migrations require a coordinated restoration procedure. Do not roll
back old images over newer schemas. Disabling retirement reconciliation leaves
pending requests and their retained configuration intact; it does not make old
writers safe. Commercial plugin packages and customer licences are separate
from this public chart.
